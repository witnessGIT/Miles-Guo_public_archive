# Miles-Guo_public_archive Agent Permissions

Policy version: `agent-permissions-v2.3`

This repository separates **management/admin Agents** from **worker Agents**, while authorizing all Agents with effective GitHub write capability to directly execute claimed archive business work.

## Repository-owner execution directive

The repository owner has explicitly authorized continuous multi-Agent execution with this target:

```text
keep claiming and completing eligible video-archive tasks
→ pass the required Pilot quality gates without lowering standards
→ continue into FULL_ARCHIVE after those gates pass
→ keep working until all eligible public video archive work is complete
```

For ordinary archive/business work, an Agent with repository write capability:

- does **not** need a PR;
- does **not** need repeated per-task user approval;
- may push its own valid claim and claimed-task outputs directly to `main`;
- must refresh repository state and claim the next eligible task after finishing one;
- must not stop merely because one task, livestream, case, or micro-batch finished.

This repository policy cannot create GitHub access for an account that does not actually have repository write permission. Authentication and GitHub repository authorization still apply.

## Role resolution

Administrative GitHub login:

```text
witnessGIT
```

An Agent may act as `admin` only when the authenticated GitHub login is verified as exactly `witnessGIT`, or the repository owner explicitly grants an admin exception in the current interaction. If identity cannot be verified, the Agent MUST act as `worker`.

## Admin Agent

Admin Agents may fix repository bugs; change `scripts/`, `schema/`, `.github/`, workflow/claim logic and coordination policy; resolve data-contract incompatibilities; modify task orchestration; resolve bug reports; and perform normal business tasks.

Admin Agents also follow continuous execution: after a repair or business task is complete, refresh current state and continue with the next eligible project task while the session remains active.

## Worker Agent

Workers perform claimed project tasks. They do not redesign or repair the project control plane.

A worker may:

- read all repository rules and project context;
- claim an eligible business or playback task;
- push its valid claim directly;
- create/update business data or report outputs required by that claim;
- push those claimed business outputs directly to `main` without a PR;
- create its own claim/completion/readiness metadata;
- create its own immutable `coordination/pr_reservations/` record on an external task PR;
- create `coordination/playback_requests/<CASE>/<SEGMENT>.json` for its own claimed playback task;
- read durable `data/playback_evidence/<CASE>/<SEGMENT>/evidence.{json,md}` generated by the repository service;
- create `coordination/playback_acceptances/<CASE>/<SEGMENT>.json` after actually reading and accepting that evidence;
- create `coordination/source_fetch_requests/<TASK_ID>/<agent_id>.json` for its own active C1 claim;
- read durable `data/source_page_evidence/<site>/<page_id>/evidence.json` generated by the repository service;
- submit a NEW immutable bug report under `coordination/bug_reports/`;
- continue to another safe task after reporting a non-blocking bug;
- keep repeating the claim → work → validate → push → finish → next-claim loop until a real stop condition exists.

A worker MUST NOT:

- patch `scripts/`, `schema/`, `tests/`, `.github/`, task orchestration, workflow rules, permissions, or other protected control-plane files;
- edit the Playback Evidence Service implementation to make its own request pass;
- manufacture or directly rewrite service-generated `data/playback_evidence/`;
- manufacture or directly rewrite service-generated `data/source_page_evidence/`;
- accept evidence it has not read;
- change schema merely to make its own data fit;
- alter another Agent's claim or bug report;
- silently work around a repository bug by changing global behavior;
- declare a bug resolved.

The repository Playback Evidence Service is maintained by admin Agents but **used by workers**. Workers do not need local `ffmpeg`, `ffprobe`, `yt-dlp`, Whisper, or a graphical video player when the service is available.

The repository Source Page Evidence Service is likewise maintained by admin Agents and used by
workers. It turns an owned C1 request into a complete, durable parsed page so a limited ordinary
chat web reader does not force a false `HOST_STOP`.

## Non-blocking bug rule

A worker that discovers a control-plane bug must create a bug report under:

```text
coordination/bug_reports/
```

If other eligible archive work exists, reporting that bug is **not** a stop condition. The worker must refresh the queue and continue on another compatible task. Only a bug that blocks all remaining eligible work can contribute to a stop classification.

## Playback worker boundary

Preferred playback chain:

```text
worker claims P9-PLAYBACK-*
  -> worker submits playback request
  -> GitHub Actions decodes real media with ffmpeg/ffprobe
  -> offline whisper.cpp produces timestamped ASR
  -> frame OCR / optional SmolVLM2 adds visual evidence
  -> service writes durable evidence to Git
  -> worker reads evidence.md/json
  -> worker submits acceptance only if content evidence matches
  -> service creates canonical-crosschecked qualifying playback record
```

A worker acceptance is a business-task decision. Modifying the scripts/workflow that produced the evidence remains an admin-only action.

## Bug reporting

Workers report bugs by creating one immutable file per bug:

```text
coordination/bug_reports/BUG_<UTC>_<TASK_ID>_<short-name>.json
```

Required fields should include `bug_id`, `status=open`, `requires_admin=true`, timestamps, Agent/login identity, task ID, severity/category, summary, concrete evidence and affected paths. Workers create new reports only; Admin Agents may later mark them resolved.

## Protected control plane

The machine-readable protected path list is in `coordination/AGENT_PERMISSIONS.json`.

Core principle:

```text
worker = directly execute/push claimed project tasks + use repository services + report bugs + continue
admin  = all worker capabilities + maintain/fix project machinery
```

The purpose of keeping the control plane admin-only is **not** to slow workers down. It prevents many concurrent Agents from changing shared orchestration while still allowing them to work directly on the archive in parallel.
