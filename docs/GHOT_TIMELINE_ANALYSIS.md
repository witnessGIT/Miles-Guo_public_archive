# Miles-Guo_public_archive GHOT Timeline Analysis

Project: `Miles-Guo_public_archive`  
Task: `P2-GHOT-TIMELINE`  
Verified: `2026-09-13`

This document records only behavior checked against real public GHOT pages. It does not treat unperformed playback checks as passes.

## Scope

This task evaluates whether GHOT can provide a usable public time axis for archive segments and for later alignment of curated GWINS text.

Verified examples include:

```text

https://ghot.ai/archive/videos/2018-03-04-2
https://ghot.ai/archive/videos/2019-05-30-2

https://ghot.ai/archive/videos/2022-05-11-2

```

A known low-quality edge case was also checked at:

```text

```

## Transcript source type

GHOT's archive list explicitly warns that video transcripts are generated by tools / AI rather than manually entered. Therefore GHOT transcript text must be modeled as machine-derived text (`text_asr` or equivalent provenance), not as curated text.

The visible label `来源 · 可读稿` is a presentation label and is not evidence that the text was human curated.

Do not overwrite GWINS curated text with GHOT text.

### Timestamp granularity

The public display examined in this task exposes timestamps at **whole-second granularity**. No verified sub-second source timestamps were observed.

For source preservation:

```text
start_sec = displayed GHOT anchor converted to seconds
```

should be retained with GHOT provenance.

An explicit source `end_sec` was not observed in the ordinary transcript rows examined here. Do **not** silently label the next segment's start as a verified GHOT end time. If a downstream process derives a provisional end from the next start, that must be separately marked as derived and not source-verified.

## Playback-anchor meaning

GHOT states that clicking the displayed timestamp can jump to the corresponding playback position. This makes the transcript start timestamps valuable as public timing candidates.

However, this task did not manually playback-audit every timestamp. Therefore the correct archive status is:

```text
timestamp_source = ghot
timestamp_granularity = second
playback_verified = false   # until actually checked
```

Actual playback-position accuracy belongs to the later audit task and must not be inferred merely because a clickable anchor exists.

## Selected clips

GHOT exposes a dedicated page:

```text
https://ghot.ai/archive/clips
```

The page describes these as selected video clips that can be played while viewing the original-video time anchor and text subtitle. The homepage also exposes examples with clip durations (for example 115s and 170s in the observed snapshot).

This confirms that GHOT has a concept of bounded video ranges in addition to ordinary transcript start anchors.

The exact machine-readable clip start/end field names or a stable public clip API were **not** verified in this task. Do not invent them. During Pilot collection, a clip range may be stored as authoritative only after its actual start/end values are directly observed and preserved with the clip/source URL.

## ASR quality limitations

Quality varies materially across records.

### Good / usable cases

Several checked pages contain dense, sequential, semantically coherent fragments with second-level anchors. Examples include `2023-01-26-1`, `2021-09-02-2`, `2018-03-04-2`, and large portions of `2019-05-30-2`.

These are suitable as candidate alignment scaffolding for curated text.

### No-transcript / special cases

A checked one-minute record (`2018-11-25-3`) reports that the video does not require transcript text. Other pages can show transcript-loading or unavailable states.

Collectors must preserve transcript status rather than treating every GHOT video as having usable ASR.

### Low-quality cases

The checked `2020-10-01-3` indexed transcript contains severe recognition noise, repeated tokens, unrelated multilingual fragments and malformed phrases. Another checked record (`2021-10-29-1`) exposes low-quality fragments and inconsistent transcript-status wording in indexed output.

This proves that GHOT timestamps can remain useful even when the associated ASR text is too noisy for direct quotation or high-confidence alignment.

Archive fields should therefore separate at least:

```text
text_asr
start_sec
alignment_quality
review_status
source_verified
```

A timestamp should not inherit text-quality confidence automatically, and a readable sentence should not inherit timing accuracy automatically.

## Dynamic-loading limitation

Transcript areas can show `正在加载转写…`, while indexed/fallback representations contain transcript excerpts. This reinforces the earlier structural finding that GHOT uses at least partly dynamic loading/hydration.

Collectors must distinguish:

```text
page exists
transcript status
transcript data successfully retrieved
```

and must not convert a temporary loading/fetch failure into `no transcript`.

## Suitability for aligning curated GWINS text

Conclusion: **GHOT is suitable as a timing candidate source, but not as an automatically trusted final time truth.**

Recommended Pilot alignment order:

1. Preserve any explicit curated timestamp already present in the curated source.
2. Otherwise fuzzy-match curated GWINS text against ordered GHOT ASR segments.
3. Use GHOT `start_sec` values as candidate anchors only when the textual match and sequence order are strong.
4. Preserve the matched GHOT segment IDs/source URL and matching evidence.
5. Assign `alignment_quality` and `review_status` explicitly.
6. For important or ambiguous segments, perform real playback verification.
7. Use local ASR only when public timing data is inadequate.

Suggested method label when this path is used:

```text
alignment_method = ghot_asr_fuzzy
```

The method label alone is not a quality guarantee.

## Pilot quality guidance

A future alignment implementation should prefer monotonic matching across neighboring segments rather than independent single-sentence matches. This reduces false matches caused by repeated phrases such as greetings, filler words or slogans.

Useful evidence for a match includes:

```text
same confirmed livestream identity
ordered text similarity
neighboring-segment consistency
reasonable temporal progression
absence of large contradictory text blocks
```

Do not merge or align records merely because they share a date or similar title.

## Data fields recommended from GHOT transcript rows

For each preserved GHOT transcript fragment:

```text
source_site = ghot
source_page_id
source_url
source_segment_order
text_asr
start_sec
end_sec = null unless explicitly observed
source_timestamp_text
transcript_status
retrieved_at
playback_verified
review_status
```

If later processing derives an end time or corrected timestamp, preserve both source and derived values/provenance rather than overwriting the source anchor.

## Decision

`P2-GHOT-TIMELINE`: **PASS for Pilot use as a candidate public time axis, with mandatory quality flags and later playback audit.**

GHOT should not be treated as a human transcript source, and its ASR should not replace curated GWINS text. Its strongest value for the Pilot is the ordered second-level timing scaffold plus source-video linkage.
