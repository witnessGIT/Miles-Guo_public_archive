# 视频目录与视频要点规则

## 目录边界

项目的第一阶段目录以“独立视频”而不是“是否为直播”为边界。每个经来源归并后不重复的视频都保留一条正式视频记录；YouTube、Rumble、Odysee、GETTR、GWINS 等同一内容的镜像只作为该视频的不同来源，不重复计数。

现有 `LIVE_...` 标识继续表示已经确认的直播身份，但采访、短视频、连线、平台更新和其他独立视频不再因为“不是直播”而被排除。它们使用 `VIDEO_...` 标识进入统一目录。

## 内容分类

视频按标题、来源元数据、已有正式身份以及后续文字稿或播放核对分类：

- `livestream`：直播；
- `short_video`：标题或内容明确为短视频、小视频；
- `interview`：采访、访谈或专访；
- `call_or_linkup`：电话、通话或连线；
- `platform_update`：GETTR 等平台上的独立更新；
- `standalone_video`：确认是独立视频，但现有证据不足以细分；
- `other_video`：其他视频，等待内容复核。

分类可以在文字稿或播放证据增加后细化，但不得为了填满类别而猜测。一个视频可有多个 `content_tags`，例如直播采访可以同时带有 `livestream` 和 `interview` 标签，而主类型保留为直播。

## 视频要点

对外统一使用“视频要点”，不再使用“直播要点”。要点必须基于完整、质量合格的文字稿或合法时间定位生成，并关联对应 `VIDEO_...`。项目内部已有 `key_points_topics` 阶段名和数据库字段暂时保留，以避免破坏现有数据和工作流；它们在语义上均解释为视频要点与主题。

`data/current/video_catalog/date_first_video_catalog.jsonl` 包含 2,785 个互不重复的独立视频：

| 主类型 | 数量 |
| --- | ---: |
| 直播 | 1,903 |
| 独立视频、待进一步细分 | 466 |
| 平台更新 | 291 |
| 其他视频、待内容复核 | 66 |
| 采访 | 31 |
| 连线或通话 | 21 |
| 明确短视频 | 7 |

其中 1,750 条关联项目原有正式直播身份；另外 153 条由来源标题明确标注为直播，但仍保留来源证据级别，未冒充原有 `LIVE_...` 身份。通用独立视频和其他视频将在取得文字稿或播放证据后继续细分。
